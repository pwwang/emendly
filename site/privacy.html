Privacy Policy

Emendly is a desktop tool, not a service. This page explains exactly what it does with your data — and, more importantly, what it never does. It is written to be read, not to be survived.

1. What Emendly does not collect

  • No keystrokes. Emendly has no keyboard hook, no keylogger and no input monitor. It reads text only from the focused field, only after you press the hotkey.
  • No document text. Your text is never sent to us. We operate no server that receives it.
  • No analytics or telemetry. There is no usage reporting, no crash reporting, no session recording and no device fingerprinting.
  • No accounts. Emendly has no sign-up, no login and no user identifier of any kind.
  • No advertising or tracking SDKs. The desktop app ships with none.

This website itself is static. It sets no cookies and loads no third-party scripts, fonts or trackers. GitHub Pages, which hosts it, may keep standard server logs for security and abuse prevention under GitHub's own privacy statement.

2. Where your text goes

When you press the hotkey and choose an action, Emendly reads the selected text (or the surrounding field for Compose) and sends it — together with the action's system prompt — directly from your computer to the model endpoint you configured in Settings (base_url and model name). That request is an ordinary HTTPS (or, for a local server, plain HTTP to your own machine) call to a host of your choosing.

There is no Emendly relay, proxy or intermediary in that path. The receiving provider handles the text under its own terms and privacy policy, so choose a provider you trust: a hosted API, an Anthropic-compatible proxy, or a local Ollama or LM Studio server on localhost for a fully offline setup.

Nothing is transmitted until you explicitly trigger an action. Closing the app sends nothing.

3. Files stored on your device

Emendly stores a small amount of configuration and diagnostic data locally. None of it contains your document text.

Local files and their contents
Path (Windows)What it holds
%APPDATA%\Emendly\settings.json Preferences: hotkey, target language, base URL, model name, per-app behaviour. It never contains your API key.
%LOCALAPPDATA%\Emendly\app-rules.json Per-application capture strategy overrides you have set, so each app is read the same reliable way next time.
%APPDATA%\Emendly\emendly.log Optional, metadata-only log: action name, app name, latency, input and output byte counts, status. Zero user text.
%APPDATA%\EmendlyPro\ Pro only: saved prompts, glossary, tone presets, local run history and the licence key. Kept on your machine.

You can delete any of these files at any time; Emendly recreates what it needs on next launch. Uninstalling removes the program; these data files remain until you delete them, so your settings survive a reinstall.

4. API keys

Your model provider key is read from the EMENDLY_API_KEY environment variable, or from the operating system keychain. It is never written into settings.json and never sent anywhere except to the model endpoint you configured, as the standard Authorization header for that request.

Emendly has no way to receive your key and no reason to.

5. Optional update check

Emendly can check whether a newer release exists by making a single HTTPS GET request to the GitHub Releases API. That request carries only a standard User-Agent: Emendly/<version> header — no machine ID, no account, no usage data and no text.

You can turn this off entirely in Settings. Automatic checks are also rate-limited: at most once every 24 hours, only on startup, and only while the setting is enabled.

6. Pro licence verification

The Pro licence is a signed key verified offline on your device using an ECDSA public signature. Emendly does not phone home to validate it, so activating Pro requires no network connection and creates no record on any server of ours.

The free, MIT-licensed build contains no licence check at all.

7. Children and legal basis

Emendly is a general-purpose productivity tool, not directed at children. Because it collects no personal data, there is no processing to which a legal basis under the GDPR would attach on our side. Where you choose to send text to a third-party model provider, that provider is the controller of that data and its policy governs it.

8. Changes to this policy

If this policy changes, the effective date above changes with it and the new version is published on this page. Because the software collects nothing, we do not expect material changes.
